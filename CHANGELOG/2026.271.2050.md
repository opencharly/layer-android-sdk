# 2026.271.2050 — feat(skills): author the owning android-sdk skill entity (#291)

## Summary

The `android-sdk` candy repo declared **no `skill:` entity**, so no owning
`/charly-check:android-sdk` skill was projected into the marketplace corpus and the
repo's `AGENTS.md` R0 list had no owning skill to name (#291).

The org convention (every candy in the corpus follows it) is a **sibling top-level
entity** named `<candy>-skill:` — NOT a nested block inside the candy node. This adds
that entity (`name`/`family`/`owner`/`description`/`content`) as a new top-level node
in `charly.yml`.

Refs #286, #291

The entity is a **sibling** of the candy node (`android-sdk-skill:`), matching the
convention every projected candy uses (e.g. `ripgrep-skill:`). It is **documentation
data** — the `skill:` body becomes a corpus page; no candy field, package, pin, or
behavior changes.

**Corpus projection ordering:** the projected `SKILL.md` is produced by
`charly marketplace generate` in the **marketplace** repo, whose refs list pins THIS
repo's merged tag. The projection is therefore observable only **after this PR merges and
tags** — the standard producer→projection ordering; it cannot be shown pre-merge from
this repo. `charly box validate` is blocked org-wide by the in-flight schema-versioning
transition (a separate cutover), so the structural evidence here is the YAML parse + the
entity-presence grep above.
